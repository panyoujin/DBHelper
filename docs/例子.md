# 常用 SQL 写法示例（IN / NOT IN / LIKE / LIMIT）

> 环境假设：MySQL（`type="mysql"`）。三种占位符语法回顾：
>
> | 语法 | 替换方式 | 是否受白名单约束 |
> |---|---|---|
> | `@@key@@` | 参数化占位符 `?key`，值由 Dapper 绑定 | 否，任意值都安全 |
> | `<%= ... @@key@@ ... %>` | 参数化 + **key 缺失时整块删除**（动态条件） | 否，任意值都安全 |
> | `<R%= @@key@@ %R>` | 值直接拼进 SQL 文本 | **是**，须过字符白名单 |
>
> 白名单详见 [Raw替换占位符白名单说明.md](./Raw替换占位符白名单说明.md)。
>
> **注意：参数化占位符不需要在 `@@` 前手写 `?`**——解析器会自动把 `@@key@@` 替换为 `?key`（MySQL）/ `@key`（SQL Server），手写 `?@@key@@` 会生成 `??key`。比较运算符照常书写并留空格，如 `= @@key@@` 会生成 `= ?key`。

---

## 1. IN

> **选型规则：数值列表直接用 `IN`（原始替换）；只有字符串列表才用 `FIND_IN_SET`。**

### 1.1 数值列表：IN + 原始替换（首选）

数字、逗号、空格都在白名单内，`<R%= %R>` 直接拼列表，能正常走索引：

```xml
<Data name="GetUsersByIds" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE `status`= @@status@@ AND `id` IN (<R%= @@ids@@ %R>)
  </SqlDefinition>
</Data>
```

```csharp
var dic = new Dictionary<string, object>();
dic["status"] = 1;
dic["ids"] = string.Join(",", channelIDList);    // "1,2,3"，代码侧拼接，禁止用户输入直传

var list = SQLHelperFactory.Instance.QueryForList("GetUsersByIds", dic);
```

空列表兜底：`IN ()` 是语法错误，传 `"NULL"` 使条件恒不匹配（返回空结果）：

```csharp
dic["ids"] = channelIDList.Count == 0 ? "NULL" : string.Join(",", channelIDList);
```

### 1.2 字符串列表：FIND_IN_SET（首选）

字符串值含引号，过不了白名单，不能用 `<R%= %R>` 拼接；改用 `FIND_IN_SET`，整个列表作为**一个普通参数**传入，值不进 SQL 文本、不受白名单约束：

```xml
<Data name="GetUsersByNames" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE `status`= @@status@@
    <%= AND FIND_IN_SET(`name`, @@names@@) %>
  </SqlDefinition>
</Data>
```

```csharp
dic["names"] = string.Join(",", nameList);    // "张三,李四"；中文、特殊字符都安全
```

特点与注意：

1. 全程参数化，key 缺失时整块删除（动态条件）
2. `FIND_IN_SET` 无法使用索引，小表/低频查询无碍；大表高频查询用 1.3
3. 列表元素本身不能含逗号（逗号是 `FIND_IN_SET` 的分隔符）

### 1.3 字符串列表走索引：固定槽位 OR 块

字符串列表量大、高频、需要走索引时，用 `<%= %>` 条件块预定义槽位：

```xml
<%= OR `name`= @@name1@@ %>
<%= OR `name`= @@name2@@ %>
<%= OR `name`= @@name3@@ %>
```

```csharp
dic["name1"] = "张三";
dic["name3"] = "李四";
// name2 不传 → 对应的 OR 块整块删除，等价于 WHERE status=?status OR name=?name1 OR name=?name3
```

利用"key 缺失整块删除"的特性实现动态 OR 列表。缺点是条件个数需在模板里预先定义。

### 1.4 两种错误写法（不要用）

```xml
<!-- 错误 1：@@ids@@ 是参数化占位符，整个列表变成单个字符串 '1,2,3'；
     MySQL 隐式类型转换把 '1,2,3' 转成 1，静默变成 IN (1)，只命中 id=1 且不报任何错 -->
<%= AND `id` IN (CONCAT(@@ids@@)) %>

<!-- 错误 2：解析器不支持嵌套。<%= %> 块先整体求值，内层 <R%= %R> 残留为字面文本，
     之后 ReplaceMC 按原文匹配不到，最终 SQL 出现裸的 <R%= ... %R> 导致语法错误 -->
<%= AND `id` IN (<R%= @@ids@@ %R>) %>
```

## 2. NOT IN

数值列表：与 IN 同构，直接 `NOT IN` + 原始替换：

```xml
<SqlDefinition>
  SELECT * FROM `user` WHERE `status`= @@status@@
  AND `dept_id` NOT IN (<R%= @@excludeDeptIds@@ %R>)
</SqlDefinition>
```

```csharp
dic["status"] = 1;
dic["excludeDeptIds"] = excludeDeptIds.Count == 0
    ? "NULL"
    : string.Join(",", excludeDeptIds);   // "5,6,7"
```

字符串列表：`FIND_IN_SET` 取反：

```xml
<%= AND NOT FIND_IN_SET(`name`, @@excludeNames@@) %>
```

```csharp
dic["excludeNames"] = string.Join(",", excludeNames);   // "已离职,冻结"
```

字符串列表量大且需要走索引时，参考 1.3 用 OR 块组合 `AND `name` <> @@name1@@` 的形式。

## 3. LIKE

**核心原则：通配符 `%` 放在参数值里传，不要拼进 SQL 文本。** LIKE 的值走参数化绑定，中文、`%`、`_` 等任意字符都安全，与白名单无关。

### 3.1 通配符写在参数值里（推荐）

```xml
<SqlDefinition>
  SELECT * FROM `user` WHERE `status`= @@status@@
  <%= AND `name` LIKE @@name@@ %>
</SqlDefinition>
```

```csharp
dic["name"] = "%张%";    // 中文、% 都是普通参数值，安全
```

### 3.2 用 CONCAT 在 SQL 内拼接通配符

```xml
<SqlDefinition>
  SELECT * FROM `user` WHERE `status`= @@status@@
  <%= AND `name` LIKE CONCAT('%', @@name@@, '%') %>
</SqlDefinition>
```

```csharp
dic["name"] = "张";      // 值里不用写 %
```

### 3.3 错误写法（不会生效）

```xml
<!-- 错误：?name 在引号内不会被解析为参数占位符，% 也会变成字面量 -->
<%= AND `name` LIKE '%?@@name@@%' %>
```

## 4. LIMIT（分页）

LIMIT 的两个值用参数化占位符传入（MySQL Connector 支持 `LIMIT ?` 参数绑定）：

```xml
<Data name="GetUserPage" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE `status`= @@status@@ ORDER BY `id` DESC
    LIMIT @@offset@@, @@size@@
  </SqlDefinition>
</Data>
```

```csharp
int page = 2, size = 20;
dic["status"] = 1;
dic["offset"] = (page - 1) * size;
dic["size"] = size;
```

最终 SQL：

```sql
SELECT * FROM `user` WHERE `status`=?status ORDER BY `id` DESC LIMIT ?offset, ?size
```

> 框架本身提供 `QueryMultipleByPage` 内置分页能力，简单分页可直接使用，不必手写 LIMIT。

## 5. 组合示例：动态条件 + IN + LIKE + 分页

```xml
<Data name="QueryUsers" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE (1=1)
    <%= AND `status`= @@status@@ %>
    <%= AND FIND_IN_SET(`dept_id`, @@deptIds@@) %>
    <%= AND `name` LIKE CONCAT('%', @@name@@, '%') %>
    ORDER BY `id` DESC
    LIMIT @@offset@@, @@size@@
  </SqlDefinition>
</Data>
```

```csharp
var dic = new Dictionary<string, object>();
dic["status"] = 1;
dic["deptIds"] = string.Join(",", deptIds);   // "2,3"，数字/字符串列表都适用
dic["name"] = "张";
dic["offset"] = 0;
dic["size"] = 20;

var list = SQLHelperFactory.Instance.QueryForList("QueryUsers", dic);
```

说明：

1. `WHERE (1=1)` 用于兜底：当所有可选条件块都被删除时，SQL 依然合法
2. `FIND_IN_SET` 包在 `<%= %>` 块里：不传 `deptIds` 时整个条件整块删除
3. `dept_id` 是数值列，本应按选型规则用 1.1 的 `IN`；但解析器不支持嵌套（见 1.4），数值列表**作为动态可选条件**时只能用 `FIND_IN_SET` 实现。若条件恒存在，直接写 `AND `dept_id` IN (<R%= @@deptIds@@ %R>)` 并用空列表传 `"NULL"` 兜底
4. 所有条件与 LIMIT 全部参数化（原始替换除外），值可含中文、特殊字符

## 常见坑速查

| 坑 | 说明 |
|---|---|
| `<%= %>` 块跨行书写 | 正则不支持换行，块会失配并原样保留在 SQL 里，条件必须写在同一行 |
| 在 `@@` 前手写 `?` | 解析器自动把 `@@key@@` 生成 `?key`，手写会变成 `??key`；比较运算符照常写并留空格，如 `= @@key@@` 生成 `= ?key` |
| `IN (CONCAT(@@list@@))` 写法 | 列表作为单个字符串 `'1,2,3'` 绑定，MySQL 隐式转换后静默变成 `IN (1)`；集合匹配请按类型选 IN（1.1）或 FIND_IN_SET（1.2） |
| `<R%= %R>` 嵌套在 `<%= %>` 中 | 解析器不支持嵌套，内层块残留为字面文本导致语法错误（见 1.4） |
| 用 `<R%= %R>` 传字符串列表 | 值含引号会被白名单拒绝；字符串列表改用 FIND_IN_SET（1.2）或固定槽位 OR 块（1.3） |
| 数值列表需要"缺参整块删除" | 原始替换不支持嵌套在 `<%= %>` 里；动态可选条件用 FIND_IN_SET 实现，或条件恒存在 + 空列表传 `"NULL"` 兜底（1.1 / 第 5 节） |
| `'%?name%'` 写法 | 引号内的占位符不会被解析，LIKE 请用 3.1 / 3.2 |
| 期望传 `List<T>` 自动展开 IN | 框架不支持 Dapper 列表展开，需先 `string.Join(",", list)` 再按类型选写法（1.1 / 1.2） |
| FIND_IN_SET 的限制 | 仅用于字符串列表（数值列表直接用 IN，见 1.1）；不走索引；元素本身不能含逗号 |
| LIMIT 用 `<R%= %R>` | 没必要，`@@offset@@ / @@size@@` 参数化即可，更安全 |
