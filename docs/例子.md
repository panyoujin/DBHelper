# 常用 SQL 写法示例（IN / NOT IN / LIKE / LIMIT）

> 环境假设：MySQL（`type="mysql"`）。三种占位符语法回顾：
>
> | 语法 | 替换方式 | 是否受白名单约束 |
> |---|---|---|
> | `@@key@@` | 参数化占位符 `?key`，值由 Dapper 绑定 | 否，任意值都安全 |
> | `<%= ... @@key@@ ... %>` | 参数化 + **key 缺失时整块删除**（动态条件） | 否，任意值都安全 |
> | `<R%= @@key@@ %R>` | 值直接拼进 SQL 文本 | **是**，须过字符白名单 |
>
> 白名单详见 [Raw替换占位符白名单说明.md](./Raw替换占位符白名单说明.md)。
>
> **注意：参数化占位符不需要在 `@@` 前手写 `?`**——解析器会自动把 `@@key@@` 替换为 `?key`（MySQL）/ `@key`（SQL Server、PostgreSQL），手写 `?@@key@@` 会生成 `??key`。比较运算符照常书写并留空格，如 `= @@key@@` 会生成 `= ?key`。

---

## 1. IN

> **选型规则：数值列表直接用 `IN`（原始替换）；只有字符串列表才用 `FIND_IN_SET`。**

### 1.1 数值列表：IN + 原始替换（首选）

数字、逗号、空格都在白名单内，`<R%= %R>` 直接拼列表，能正常走索引：

```xml
<Data name="GetUsersByIds" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE `status`= @@status@@ AND `id` IN (<R%= @@ids@@ %R>)
  </SqlDefinition>
</Data>
```

```csharp
var dic = new Dictionary<string, object>();
dic["status"] = 1;
dic["ids"] = string.Join(",", channelIDList);    // "1,2,3"，代码侧拼接，禁止用户输入直传

var list = SQLHelperFactory.Instance.QueryForList("GetUsersByIds", dic);
```

空列表兜底：`IN ()` 是语法错误，传 `"NULL"` 使条件恒不匹配（返回空结果）：

```csharp
dic["ids"] = channelIDList.Count == 0 ? "NULL" : string.Join(",", channelIDList);
```

### 1.2 字符串列表：FIND_IN_SET（首选）

字符串值含引号，过不了白名单，不能用 `<R%= %R>` 拼接；改用 `FIND_IN_SET`，整个列表作为**一个普通参数**传入，值不进 SQL 文本、不受白名单约束：

```xml
<Data name="GetUsersByNames" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE `status`= @@status@@
    <%= AND FIND_IN_SET(`name`, @@names@@) %>
  </SqlDefinition>
</Data>
```

```csharp
dic["names"] = string.Join(",", nameList);    // "张三,李四"；中文、特殊字符都安全
```

特点与注意：

1. 全程参数化，key 缺失时整块删除（动态条件）
2. `FIND_IN_SET` 无法使用索引，小表/低频查询无碍；大表高频查询用 1.3
3. 列表元素本身不能含逗号（逗号是 `FIND_IN_SET` 的分隔符）

### 1.3 字符串列表走索引：固定槽位 OR 块

字符串列表量大、高频、需要走索引时，用 `<%= %>` 条件块预定义槽位：

```xml
<%= OR `name`= @@name1@@ %>
<%= OR `name`= @@name2@@ %>
<%= OR `name`= @@name3@@ %>
```

```csharp
dic["name1"] = "张三";
dic["name3"] = "李四";
// name2 不传 → 对应的 OR 块整块删除，等价于 WHERE status=?status OR name=?name1 OR name=?name3
```

利用"key 缺失整块删除"的特性实现动态 OR 列表。缺点是条件个数需在模板里预先定义。

### 1.4 两种错误写法（不要用）

```xml
<!-- 错误 1：@@ids@@ 是参数化占位符，整个列表变成单个字符串 '1,2,3'；
     MySQL 隐式类型转换把 '1,2,3' 转成 1，静默变成 IN (1)，只命中 id=1 且不报任何错 -->
<%= AND `id` IN (CONCAT(@@ids@@)) %>

<!-- 错误 2：解析器不支持嵌套。<%= %> 块先整体求值，内层 <R%= %R> 残留为字面文本，
     之后 ReplaceMC 按原文匹配不到，最终 SQL 出现裸的 <R%= ... %R> 导致语法错误 -->
<%= AND `id` IN (<R%= @@ids@@ %R>) %>
```

## 2. NOT IN

数值列表：与 IN 同构，直接 `NOT IN` + 原始替换：

```xml
<SqlDefinition>
  SELECT * FROM `user` WHERE `status`= @@status@@
  AND `dept_id` NOT IN (<R%= @@excludeDeptIds@@ %R>)
</SqlDefinition>
```

```csharp
dic["status"] = 1;
dic["excludeDeptIds"] = excludeDeptIds.Count == 0
    ? "NULL"
    : string.Join(",", excludeDeptIds);   // "5,6,7"
```

字符串列表：`FIND_IN_SET` 取反：

```xml
<%= AND NOT FIND_IN_SET(`name`, @@excludeNames@@) %>
```

```csharp
dic["excludeNames"] = string.Join(",", excludeNames);   // "已离职,冻结"
```

字符串列表量大且需要走索引时，参考 1.3 用 OR 块组合 `AND `name` <> @@name1@@` 的形式。

## 3. LIKE

**核心原则：通配符 `%` 放在参数值里传，不要拼进 SQL 文本。** LIKE 的值走参数化绑定，中文、`%`、`_` 等任意字符都安全，与白名单无关。

### 3.1 通配符写在参数值里（推荐）

```xml
<SqlDefinition>
  SELECT * FROM `user` WHERE `status`= @@status@@
  <%= AND `name` LIKE @@name@@ %>
</SqlDefinition>
```

```csharp
dic["name"] = "%张%";    // 中文、% 都是普通参数值，安全
```

### 3.2 用 CONCAT 在 SQL 内拼接通配符

```xml
<SqlDefinition>
  SELECT * FROM `user` WHERE `status`= @@status@@
  <%= AND `name` LIKE CONCAT('%', @@name@@, '%') %>
</SqlDefinition>
```

```csharp
dic["name"] = "张";      // 值里不用写 %
```

### 3.3 错误写法（不会生效）

```xml
<!-- 错误：?name 在引号内不会被解析为参数占位符，% 也会变成字面量 -->
<%= AND `name` LIKE '%?@@name@@%' %>
```

## 4. LIMIT（分页）

LIMIT 的两个值用参数化占位符传入（MySQL Connector 支持 `LIMIT ?` 参数绑定）：

```xml
<Data name="GetUserPage" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE `status`= @@status@@ ORDER BY `id` DESC
    LIMIT @@offset@@, @@size@@
  </SqlDefinition>
</Data>
```

```csharp
int page = 2, size = 20;
dic["status"] = 1;
dic["offset"] = (page - 1) * size;
dic["size"] = size;
```

最终 SQL：

```sql
SELECT * FROM `user` WHERE `status`=?status ORDER BY `id` DESC LIMIT ?offset, ?size
```

> 框架本身提供 `QueryMultipleByPage` 内置分页能力，简单分页可直接使用，不必手写 LIMIT。

## 5. 组合示例：动态条件 + IN + LIKE + 分页

```xml
<Data name="QueryUsers" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE (1=1)
    <%= AND `status`= @@status@@ %>
    <%= AND FIND_IN_SET(`dept_id`, @@deptIds@@) %>
    <%= AND `name` LIKE CONCAT('%', @@name@@, '%') %>
    ORDER BY `id` DESC
    LIMIT @@offset@@, @@size@@
  </SqlDefinition>
</Data>
```

```csharp
var dic = new Dictionary<string, object>();
dic["status"] = 1;
dic["deptIds"] = string.Join(",", deptIds);   // "2,3"，数字/字符串列表都适用
dic["name"] = "张";
dic["offset"] = 0;
dic["size"] = 20;

var list = SQLHelperFactory.Instance.QueryForList("QueryUsers", dic);
```

说明：

1. `WHERE (1=1)` 用于兜底：当所有可选条件块都被删除时，SQL 依然合法
2. `FIND_IN_SET` 包在 `<%= %>` 块里：不传 `deptIds` 时整个条件整块删除
3. `dept_id` 是数值列，本应按选型规则用 1.1 的 `IN`；但解析器不支持嵌套（见 1.4），数值列表**作为动态可选条件**时只能用 `FIND_IN_SET` 实现。若条件恒存在，直接写 `AND `dept_id` IN (<R%= @@deptIds@@ %R>)` 并用空列表传 `"NULL"` 兜底
4. 所有条件与 LIMIT 全部参数化（原始替换除外），值可含中文、特殊字符

## 6. 批量执行

同一 SQL key 用多组参数各执行一次，方法签名是 `ExecuteNonQuery(sqlKey, List<Dictionary<string, object>>)`——列表里的每个 `Dictionary` 执行一次，返回受影响总行数。

XML 定义（普通写法即可，与单条执行相同）：

```xml
<Data name="InsertMenu" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    INSERT INTO `menu` (`cid`, `name`, `sort`) VALUES (@@cid@@, @@name@@, @@sort@@)
  </SqlDefinition>
</Data>
```

C# 调用（每组参数执行一次）：

```csharp
var dics = new List<Dictionary<string, object>>
{
    new Dictionary<string, object> { ["cid"] = "18", ["name"] = "菜单A", ["sort"] = 18 },
    new Dictionary<string, object> { ["cid"] = "19", ["name"] = "菜单B", ["sort"] = 19 },
    new Dictionary<string, object> { ["cid"] = "20", ["name"] = "菜单C", ["sort"] = 20 },
};
int total = SQLHelperFactory.Instance.ExecuteNonQuery("InsertMenu", dics);   // 返回 3
```

注意：

1. **批量场景不能使用 `<R%= %R>` 原始替换**——框架会直接抛出"批量执行不能用在直接替换的场景"，因为每组参数的原始值不同会导致语义混乱
2. 批量执行的每组参数之间没有事务包裹，某组失败前面的组已生效；需要整体成功/失败请用第 8 节的事务方式（`ExecuteNonQuery(conn, trans, sqlKey, dics)` 重载同样支持批量列表）

## 7. 返回多结果集

XML 中一个 `<SqlDefinition>` 里写多条 SELECT（用 `;` 分隔），一次网络往返取回多个结果集。支持 2~5 个结果集。

XML 定义：

```xml
<Data name="GetDashboard" type="mysql" ConnStringName="DbContext">
  <SqlDefinition>
    SELECT `id`, `name` FROM `menu` WHERE `status` = @@status@@;
    SELECT * FROM `user` WHERE `dept_id` = @@deptId@@;
  </SqlDefinition>
</Data>
```

### 7.1 元组版（推荐，NetCore 版 C# 8.0 语法）

两个结果集各自映射到不同实体类型：

```csharp
var dic = new Dictionary<string, object> { ["status"] = 1, ["deptId"] = 100 };
var (menus, users) = SQLHelperFactory.Instance.QueryMultiple<Menu, User>("GetDashboard", dic);

foreach (var m in menus) Console.WriteLine(m.name);
foreach (var u in users) Console.WriteLine(u.name);
```

同样支持三到五个结果集：`QueryMultiple<T1, T2, T3>(...)` 返回三元元组，依此类推。

### 7.2 合并处理版（Func 委托）

需要在两个结果集之间做关联/拼接时用委托版本，委托内拿到第一个结果集 `IEnumerable<TFirst>` 和第二个 `IEnumerable<TSecond>`，返回最终合并结果：

```csharp
var rows = SQLHelperFactory.Instance.QueryMultiple<Menu, User, object>(
    "GetDashboard", dic,
    (menus, users) =>
    {
        // 在这里对两个结果集做关联处理
        return menus.Join(users, m => m.id, u => u.dept_id,
            (m, u) => new { Menu = m.name, User = u.name });
    });
```

注意：

1. 结果集顺序与 XML 中 SELECT 顺序一一对应
2. 分页场景可配合 `QueryMultipleByPage<T>(...)`：XML 里第一条 SELECT 写 `SELECT COUNT(*)`，第二条写分页数据，方法自动取回 `out total`（或元组版返回 `(IEnumerable<T>, int)`）

## 8. 事务中执行多个 SQL key

### 8.1 事务封装（推荐）

框架提供 `ExecuteInTransaction`：内部创建连接并管理提交/回滚，业务代码只写在委托里——委托正常返回自动提交，抛出异常自动回滚并原样抛出：

```csharp
// 无返回值版
SQLHelperFactory.Instance.ExecuteInTransaction(connStr, "mysql", (conn, trans) =>
{
    SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "InsertMenu", dicA);
    SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "UpdateStock", dicB);
    SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "InsertMenu", dicsBatch);   // 批量也支持
});

// 带返回值版：事务体内的查询用 Dapper 连接扩展（conn.ExecuteScalar/conn.Query，事务传 trans）
var newId = SQLHelperFactory.Instance.ExecuteInTransaction(connStr, "mysql", (conn, trans) =>
{
    SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "InsertOrder", orderDic);
    return conn.ExecuteScalar<long>("SELECT LAST_INSERT_ID()", transaction: trans);
});
```

说明：

1. `dbType` 传 `"mysql"`（默认）或 `"sqlserver"`；连接字符串也可以用 `SQLHelperFactory.Instance.ConnectionString(sqlKey, null)` 从 SQL key 配置推导
2. 委托内**不要**再自己调用 `Commit`/`Rollback`，框架统一管理
3. 委托内执行 SQL **必须**用 `ExecuteNonQuery(conn, trans, ...)` 外部事务重载——误用无连接版 `ExecuteNonQuery(sqlKey, dic)` 会创建独立连接自动提交执行，**脱离事务**且可能与事务持有的锁互相等待造成死锁
4. 委托的返回值必须**已物化**：`conn.Query<T>` 默认 buffered 是安全的；但 `QueryMultiple`/`ExecuteReader` 返回的 reader 未读完时委托返回，连接会随提交关闭，之后枚举报错
5. 回滚失败（如连接已断开）时保留原始业务异常
6. 目前只有 `ExecuteNonQuery` 提供外部事务重载；事务体内的**查询**没有对应的 sqlKey 版重载，直接用 Dapper 连接扩展（`conn.Query<T>` / `conn.ExecuteScalar<T>`，传 `transaction: trans` 即可保证在同一事务中）
7. 不要嵌套调用 `ExecuteInTransaction`：嵌套会创建两个独立事务（MySQL 无嵌套事务），外层持锁内层写同一行会锁等待

### 8.2 手动管理事务

需要精细控制（如嵌套保存点、条件性提交）时用手动方式，把外部开启的连接和事务传给 `ExecuteNonQuery` 的外部事务重载（两版均支持；连接串用 `ConnectionString(sqlKey)` 获取，NetCore 底层走 `AllHelper`、4.5 走对应库的 Helper 外部事务重载）：

```csharp
// 各 SQL key 的连接串必须一致，才能放进同一个事务
var connStr = SQLHelperFactory.Instance.ConnectionString("InsertMenu", null);
using (var conn = new MySqlConnector.MySqlConnection(connStr))
{
    conn.Open();
    using (var trans = conn.BeginTransaction())
    {
        try
        {
            // 不同的 SQL key 在同一事务中依次执行，支持单条或批量（List 版）
            SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "InsertMenu", dicA);
            SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "UpdateStock", dicB);
            SQLHelperFactory.Instance.ExecuteNonQuery(conn, trans, "InsertMenu", dicsBatch);   // 批量也支持

            trans.Commit();
        }
        catch
        {
            trans.Rollback();   // 任一失败整体回滚
            throw;
        }
    }
}
```

手动方式注意：

1. **同一个事务里的所有 SQL key 必须使用相同的连接串**（即 XML 中 `ConnStringName` 配置一致），跨库无法用本地事务——传参前可先核对 `ConnectionString(sqlKey)` 返回值
2. 事务的控制权在调用方：框架不会自动 Commit/Rollback，异常时必须自己 `Rollback`（如上例 try/catch），否则连接关闭时未提交的修改自动丢弃
3. `using (var trans = ...)` + `Commit` 后再 `Rollback` 会抛异常，所以 `Commit` 放在 try 内、`Rollback` 放在 catch 内，不要重复提交
4. 外部事务重载两版均支持（NetCore 走 `AllHelper`，4.5 直接分发到对应库的 Helper）；`conn` 必须在外部先 `Open()`，否则执行会抛"连接未打开"

## 9. PostgreSQL 支持（两版均支持）

XML 配置中 `type` 支持 `postgresql` / `postgres` / `pgsql` 三种写法，驱动为 Npgsql（MIT 协议）。解析器无需改动：`@@key@@` 自动生成 `@key` 命名参数，正是 Npgsql 的参数格式。

```xml
<Data name="GetUserList" type="postgresql" ConnStringName="PgDbContext">
  <SqlDefinition>
    SELECT * FROM "user" WHERE status = @@status@@ LIMIT @@limit@@ OFFSET @@offset@@
  </SqlDefinition>
</Data>
```

连接串关键字（与 MySQL/SQL Server 不同）：

```
Host=localhost;Port=5432;Database=mydb;Username=postgres;Password=***
```

PostgreSQL 特有差异（写 SQL 模板时注意）：

| 场景 | MySQL 写法 | PostgreSQL 写法 |
|---|---|---|
| 分页 | `LIMIT @@offset@@, @@size@@` | `LIMIT @@size@@ OFFSET @@offset@@`（两值顺序相反） |
| 字符串列表 IN | `FIND_IN_SET(\`id\`, @@ids@@)` | 不存在 FIND_IN_SET，改用 `id = ANY(@@ids@@)` 并传数组（`long[]`/`string[]`，Npgsql 原生支持数组参数） |
| 忽略大小写匹配 | `LIKE '%abc%'` | `ILIKE '%abc%'`（`LIKE` 区分大小写） |
| 标识符 | 反引号 `` `name` `` | 双引号 `"name"`；**不加引号的标识符会被自动转为小写**——建表用了大写（`"UserName"`）就必须在 SQL 里带双引号引用 |
| 自增主键取值 | `SELECT LAST_INSERT_ID()` | `RETURNING id` 子句或 `SELECT LASTVAL()` |

事务封装 `ExecuteInTransaction(connStr, "postgresql", ...)` 与 `TestConnection(name, "postgresql")` 均已支持。

> 版本说明：NetCore 版目标 .NET 8（Npgsql 8.0.5，要求 PostgreSQL 12+，如需支持更老版本 PG 可降回 Npgsql 6.x）；4.5 版目标 .NET Framework 4.8（Npgsql 6.0.10）。两版 MySQL 驱动均为 MySqlConnector 2.4.0（MIT）、Dapper 2.1.35；SQL Server 驱动 NetCore 版为 Microsoft.Data.SqlClient（.NET 8 下 System.Data.SqlClient 已废弃）。部署 4.5 版需要机器装有 .NET Framework 4.8 运行时，NetCore 版需要 .NET 8 运行时。

## 10. MariaDB 支持（两版均支持）

MariaDB 兼容 MySQL 协议与 SQL 方言，**MySqlConnector 同时原生支持两者**——无需新驱动，XML 配置中 `type` 写 `mariadb` 即可（连接串与 MySQL 完全相同，占位符同样生成 `?key`）：

```xml
<Data name="GetUserList" type="mariadb" ConnStringName="MariaDbContext">
  <SqlDefinition>
    SELECT * FROM `user` WHERE status = @@status@@ LIMIT @@start@@, @@size@@
  </SqlDefinition>
</Data>
```

说明：

1. 连接串、参数占位符（`?`）、`LIMIT x,y` 分页语法均与 MySQL 一致，MySQL 的所有写法文档（第 1~8 节）对 MariaDB 同样适用
2. 分发层按 MariaDB 路由到 MySqlHelper/MySqlConnection，`TestConnection(name, "mariadb")` 与 `ExecuteInTransaction(connStr, "mariadb", ...)` 均可用
3. MariaDB 特有差异（极少触发）：10.5+ 支持 `INSERT ... RETURNING id`；`LAST_INSERT_ID()` 两种库通用

## 常见坑速查

| 坑 | 说明 |
|---|---|
| `<%= %>` 块跨行书写 | 正则不支持换行，块会失配并原样保留在 SQL 里，条件必须写在同一行 |
| 在 `@@` 前手写 `?` | 解析器自动把 `@@key@@` 生成 `?key`，手写会变成 `??key`；比较运算符照常写并留空格，如 `= @@key@@` 生成 `= ?key` |
| `IN (CONCAT(@@list@@))` 写法 | 列表作为单个字符串 `'1,2,3'` 绑定，MySQL 隐式转换后静默变成 `IN (1)`；集合匹配请按类型选 IN（1.1）或 FIND_IN_SET（1.2） |
| `<R%= %R>` 嵌套在 `<%= %>` 中 | 解析器不支持嵌套，内层块残留为字面文本导致语法错误（见 1.4） |
| 用 `<R%= %R>` 传字符串列表 | 值含引号会被白名单拒绝；字符串列表改用 FIND_IN_SET（1.2）或固定槽位 OR 块（1.3） |
| 数值列表需要"缺参整块删除" | 原始替换不支持嵌套在 `<%= %>` 里；动态可选条件用 FIND_IN_SET 实现，或条件恒存在 + 空列表传 `"NULL"` 兜底（1.1 / 第 5 节） |
| `'%?name%'` 写法 | 引号内的占位符不会被解析，LIKE 请用 3.1 / 3.2 |
| 期望传 `List<T>` 自动展开 IN | 框架不支持 Dapper 列表展开，需先 `string.Join(",", list)` 再按类型选写法（1.1 / 1.2） |
